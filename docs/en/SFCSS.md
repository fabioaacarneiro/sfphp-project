# SFCSS — Simple Framework CSS

> Verified against the built stylesheet · 3,836 classes · 33.1KB gzipped
>
> 🌍 Also available in [Português](../pt-BR/SFCSS.md) and
> [Español](../es/SFCSS.md).

A CSS framework with **no dependencies**, generated by PHP from a config file.
It ships components (buttons, forms, navigation, modals, dropdowns, toasts…)
and utility classes (`p-3`, `md:grid-cols-2`, `text-center`…). You describe the
design once, in the config, and the builder derives everything that follows
from it: the text that stays readable on each colour, hover shades, pale
backgrounds, the dark theme, and every variant of every component.

Full class list: [utilities reference](SFCSS_UTILITIES.md).

## Installing

```html
<link rel="stylesheet" href="/assets/css/sfcss.min.css">
```

`sfcss.css` is the readable build of the same stylesheet. Nothing else is
needed — no build step in the browser, no font or icon fetched from a CDN. The
stylesheet ships in the package under `resources/assets/css`; `create-project`
and `./sfphp serve` copy it into `public/assets/`, and `./sfphp assets:publish`
does it on demand.

The interactive components (modal, dropdown, tooltip, tabs, toasts) are styled
by SFCSS and driven by SFJS; their behaviour is documented in the SFJS section
of the [documentation](DOCUMENTATION.md).

## How it is organised

```
tools/css-builder/
├── sfcss.config.json      design decisions: colours, scales, options
├── sfcss-base.css         reset, accessibility, typography, components
└── sfcss-builder.php      reads the config and writes the stylesheet
```

The stylesheet is emitted in cascade order:

1. **Tokens** — CSS variables on `:root`, and their dark-theme values.
2. **Container** — widths from the breakpoints.
3. **Reset and accessibility baseline** — targeted resets, `:focus-visible`,
   `[hidden]`, `.visually-hidden`, typography and a few layout helpers
   (`text-truncate`, `line-clamp`, `sticky-top`, `ratio`…).
4. **Components** — which read variables, never colours.
5. **Role colours and per-colour variants** — generated for every colour in
   `config.colors` (`text-primary`, `bg-primary-subtle`, `btn-primary`…).
6. **Palette** — 20 colour families × 10 shades, with `hover:` variants and
   gradient stops.
7. **Utilities** — expanded from the utility map, with state, breakpoint and
   print variants.

Colours and utilities come after the components on purpose: `m-0` or
`bg-blue-50` written on a `.card` wins without `!important`.

### Rebuilding

```bash
./sfphp css:build [--config=path] [--output=dir]
php tools/css-builder/sfcss-builder.php [config.json] [output directory]
```

In this repository `css:build` writes into `resources/assets/css` (run
`./sfphp assets:publish` afterwards); in a project that installed the
framework it writes into `public/assets/css`. The builder writes `sfcss.css`
and `sfcss.min.css`, and prints a warning for anything the reader should hear
about — a colour no text can be read on, two utilities producing the same
class.

## Customising

### A project config holds only what it changes

A project keeps its own `sfcss.config.json` — at the project root or at
`tools/css-builder/sfcss.config.json`, or passed with `--config=`. It is **merged over the defaults**, map by map, so it holds
only what the project changes:

```json
{
  "colors": { "primary": "#7c3aed", "brand": "#0f766e" },
  "options": { "prefix": "sf", "hoverVariants": false }
}
```

Maps merge key by key; a list or a scalar replaces what it overrides. An empty
map (`"colorPalettes": {}`) replaces the default with nothing.

### What the config holds

| Key | What it decides |
|---|---|
| `colors` | The role colours — `primary`, `secondary`, `success`, `danger`, `warning`, `info`, `light`, `dark`, `white`, `black` — and any you add |
| `colorPalettes` | The 20 fixed palette families, 10 shades each |
| `contrast` | The two text colours the builder chooses between (`light`, `dark`) |
| `surfaces` | Page background, raised and sunken surfaces, borders and body text — for `light` and for `dark` |
| `spacing` | The scale behind margin, padding, gap and `space-*` |
| `sizing` | The scale behind width, height, `min-h-*`, `max-h-*` and `size-*` (`min-w-*` and `max-w-*` have fixed lists) |
| `typography` | Font families, the font-size scale, line height, weights |
| `radii` | The radius scale (`DEFAULT` is plain `.rounded`) |
| `border`, `shadows`, `transition` | Border width, colour and radius (`--border-radius`), the three shadows, the default transition |
| `breakpoints` | `sm`, `md`, `lg`, `xl` — the container, every `md:` class and every responsive component read these |
| `options` | Features and behaviour, below |
| `utilities` | Additions to and removals from the utility map, below |

### Options

| Option | Default | Effect |
|---|---|---|
| `prefix` | `""` | Prefix every CSS variable: `"sf"` turns `--primary` into `--sf-primary`, for pages that load another stylesheet with its own `--primary`. Class names do not change; variables set in a `style` attribute take the prefix too (`--sf-card-padding-x`). `--sf-anchor`, which SFJS writes on popovers, keeps its name |
| `components` | `true` | `false` drops the components and their per-colour variants; the reset, accessibility baseline, typography, layout helpers, role colours, palette and utilities remain |
| `rounded` | `true` | `false` sets every radius variable to 0, so components and `rounded-*` classes are square (`rounded-full` stays round) |
| `shadows` | `true` | `false` sets every shadow variable to `none` (the `shadow-*` classes and the components that read them) |
| `transitions` | `true` | `false` sets `--transition` (the `transition` class) to `none`; components keep their own short transitions, which `reducedMotion` is what stops |
| `reducedMotion` | `true` | Honour the reader's "reduce motion" setting (see [Accessibility](#accessibility)) |
| `darkMode` | `true` | Emit the dark theme |
| `hoverVariants` | `true` | Emit `hover:` classes |
| `responsiveVariants` | `true` | Emit `sm:` `md:` `lg:` `xl:` classes |
| `importantUtilities` | `false` | Add `!important` to every class generated from the utility map (not to the palette, role colours or layout helpers) |
| `minContrast` | `4.5` | The contrast ratio "readable" means — WCAG AA for body text |
| `gradientShades` | `["500","600","700"]` | Which palette shades get `from-*` and `to-*` classes |

### Colours, and everything derived from them

For each colour in `colors` — except `white` and `black`, which get only
`--white`, `--white-rgb` and the `text-`, `bg-` and `border-` classes — the
builder computes, in both themes:

| Variable | What it is |
|---|---|
| `--primary` | The colour |
| `--primary-rgb` | Its channels, for `rgb(var(--primary-rgb) / 0.5)` |
| `--primary-contrast` | The text that stays readable on it |
| `--primary-hover`, `--primary-active` | The hover and pressed shades of a button |
| `--primary-subtle` | A pale background — alerts, toasts, list items |
| `--primary-border` | The border that goes with it |
| `--primary-emphasis` | Text that reads on the pale background |
| `--primary-text` | The colour as text on the page — darkened only as far as it must be to be readable |

"Readable" is computed, not hoped for. White text is preferred on a colour and
only loses to the dark one when it would fall below `minContrast`; a colour on
which neither reaches it is reported when the stylesheet is built. The text form
of `warning`, for instance, is the same hue darkened until it reads on white.

And each colour gets its classes, with no CSS written by hand:

```
.text-brand  .bg-brand  .border-brand       .text-bg-brand     .link-brand
.bg-brand-subtle  .border-brand-subtle  .text-brand-emphasis
.btn-brand  .btn-outline-brand  .badge-brand  .badge-brand-subtle
.alert-brand  .toast-brand  .list-group-item-brand  .table-brand
.progress-bar-brand  .spinner-brand
```

### The utility map

Most utility classes come from one map in the builder (the palette,
gradients, role colours and container are generated from the config directly,
and a few helpers live in `sfcss-base.css`). An entry says which property the
class sets, from which values, and which variants it gets:

```json
{
  "utilities": {
    "tab-size": {
      "class": "tab",
      "property": "tab-size",
      "values": { "2": "2", "4": "4", "8": "8" },
      "responsive": true
    },
    "cursor": false
  }
}
```

That adds `.tab-2`, `.tab-4`, `.tab-8` with `md:tab-4` and the other
breakpoints, and removes every `cursor-*` class.

| Field | Meaning |
|---|---|
| `class` | The prefix: `"m"` gives `m-3`. `""` uses the value's name alone (`"flex"`, `"italic"`) |
| `property` | One CSS property, or a list for classes that set several |
| `values` | A map of name → value, or `"$spacing"`, `"$sizing"`, `"$radii"`, `"$fontSizes"` to read a scale from the config. A value named `DEFAULT` gives the bare class (`.rounded`) |
| `extra` | More values, added to a scale |
| `responsive` | `true` for breakpoint variants of every value, or a list of the value names that get them |
| `states` | Pseudo-class variants, e.g. `["hover", "focus"]` — all of them are omitted when `options.hoverVariants` is `false` |
| `print` | Also emit a `print:` variant |
| `selector` | A pattern for classes that are not a plain `.name` — `"{class} > * + *"` is how `space-y-*` is written |

An entry with the name of a built-in one is merged into it, so
`"opacity": { "responsive": true }` gives `md:opacity-50` without restating the
values. `false` removes it.

Entry names are not always the class prefix. The built-in ones:

| Entry | Classes |
|---|---|
| `margin`, `margin-t`, `margin-b`, `margin-l`, `margin-r`, `margin-x`, `margin-y`, `margin-s`, `margin-e` | `m-*`, `mt-*`, `mb-*`, `ml-*`, `mr-*`, `mx-*`, `my-*`, `ms-*`, `me-*` |
| `padding`, `padding-t` … `padding-e` | `p-*`, `pt-*` … `pe-*` |
| `gap`, `gap-x`, `gap-y`, `space-y`, `space-x` | `gap-*`, `gap-x-*`, `gap-y-*`, `space-y-*`, `space-x-*` |
| `display`, `display-bare` | `d-*`; `block`, `flex`, `hidden`… |
| `flex-direction`, `flex-wrap`, `flex`, `flex-grow`, `flex-shrink` | `flex-row`…, `flex-wrap`…, `flex-1`…, `flex-grow-*`, `flex-shrink-*` |
| `justify`, `justify-items`, `items`, `content`, `self`, `place`, `order` | `justify-*`, `justify-items-*`, `items-*`, `content-*`, `self-*`, `place-*`, `order-*` |
| `grid-cols`, `grid-auto`, `col-span`, `col-start`, `row-span` | `grid-cols-*`, `grid-auto-*`, `col-span-*`, `col-start-*`, `row-span-*` |
| `width`, `height`, `min-width`, `max-width`, `min-height`, `max-height`, `size` | `w-*`, `h-*`, `min-w-*`, `max-w-*`, `min-h-*`, `max-h-*`, `size-*` |
| `font-size`, `text-align`, `font-weight`, `font-family`, `font-style` | `text-{size}`, `text-{align}`, `font-{weight}`, `font-sans`/`font-mono`, `italic`/`not-italic` |
| `leading`, `tracking`, `text-decoration`, `underline-offset`, `text-transform`, `whitespace`, `word-break`, `text-wrap`, `vertical-align` | `leading-*`, `tracking-*`, `underline`…, `underline-offset-*`, `uppercase`…, `whitespace-*`, `break-*`, `text-balance`…, `align-*` |
| `opacity`, `shadow`, `rounded`, `rounded-corners`, `transition` | `opacity-*`, `shadow-*`, `rounded-*`, `rounded-t-*`…, `transition` |
| `border`, `border-side`, `border-width`, `border-colour`, `background` | `border`, `border-t`…, `border-2`…, `border-transparent`/`current`, `bg-transparent`/`current` |
| `position`, `inset`, `top`, `bottom`, `start`, `end`, `z` | `relative`…, `inset-*`, `top-*`, `bottom-*`, `start-*`, `end-*`, `z-*` |
| `overflow`, `overflow-x`, `overflow-y`, `visibility`, `object-fit`, `aspect`, `cursor`, `pointer-events`, `select` | `overflow-*`…, `visible`/`invisible`, `object-*`, `aspect-*`, `cursor-*`, `pointer-events-*`, `select-*` |

## Themes: light, dark and automatic

The dark theme is **opt-in**. A page says what it wants on the root element:

```html
<html data-theme="dark">    <!-- always dark -->
<html data-theme="light">   <!-- always light -->
<html data-theme="auto">    <!-- follow the reader's system setting -->
```

Saying nothing stays light, so no page changes under anybody.

What changes between themes is **roles**, not colours: the surfaces, the body
text, and each colour's `-subtle`, `-border`, `-emphasis` and `-text`. Alerts,
tables, forms, cards, badges, list groups and toasts read those, so they follow
the theme with nothing written for it.

The palette classes (`bg-blue-50`, `text-slate-600`) keep their value in both
themes on purpose — `bg-blue-50` is a colour, not a role. A design that must
follow the theme uses the role classes: `bg-primary-subtle`,
`text-primary-emphasis`, `bg-body-raised`, `text-body`, `text-muted`.

## Accessibility

Built in, not optional:

- **Visible keyboard focus.** `:focus-visible` draws an outline for keyboard
  users only — a mouse click does not match it, so nobody has a reason to
  remove it. Form fields draw a focus ring and keep a transparent outline, which
  Windows high-contrast mode paints in the system colour.
- **Readable colours.** Text on a colour is chosen to reach `minContrast`
  (WCAG AA, 4.5:1). The defaults for `primary`, `success`, `danger` and `info`
  are the shades that carry white text at AA.
- **Reduced motion.** With the reader's "reduce motion" setting on, animations
  and transitions shrink to near zero (they still fire their end events for code
  that waits on them). Spinners keep turning, slowly: one that stops looks like
  a page that froze.
- **Screen-reader text.** `.visually-hidden` hides visually and keeps the text
  for assistive technology; `.visually-hidden-focusable` shows on focus, for
  skip links. `.skip-link` is a ready one: `<a class="skip-link" href="#main">`.
- **`[hidden]` means hidden**, whatever `display` a class gives the element.
- **State from ARIA.** The current tab, page or link is styled from
  `aria-selected="true"` and `aria-current="page"`, a busy region from
  `aria-busy="true"`, an invalid field from `aria-invalid="true"` — so markup
  that tells a screen reader the truth is also markup that looks right.
- **Right-to-left languages.** Components use logical properties
  (`margin-inline-start`, `text-align: start`), so a page with `dir="rtl"`
  mirrors without a second stylesheet. Utilities come in both forms:
  `ms-3` / `me-3` (start/end) beside `ml-3` / `mr-3` (left/right).

## Components

Every component reads its own variables, which a variant sets and a page can
set too — without overriding a selector:

```html
<div class="card" style="--card-padding-x: 2rem; --card-radius: 0">…</div>
<button class="btn btn-primary" style="--btn-padding-x: 2.5rem">Wide</button>
```

### Buttons

```html
<button class="btn btn-primary">Primary</button>
<button class="btn btn-outline-primary">Outline</button>
<button class="btn btn-link">Link</button>
<button class="btn">Plain</button>

<button class="btn btn-primary btn-sm">Small</button>
<button class="btn btn-primary btn-lg">Large</button>

<button class="btn btn-primary" disabled>Disabled</button>
<a class="btn btn-primary" aria-disabled="true">Disabled link</a>
<button class="btn btn-secondary" aria-pressed="true">Toggled</button>
```

Every colour has `btn-{colour}` and `btn-outline-{colour}`. The border is always
there — transparent when a variant has none — so a button beside a text field is
the same height.

**Groups and toolbars:**

```html
<div class="btn-group" role="group" aria-label="Alignment">
  <button class="btn btn-outline-primary">Left</button>
  <button class="btn btn-outline-primary">Centre</button>
  <button class="btn btn-outline-primary">Right</button>
</div>

<!-- Radio buttons that look like a button group -->
<div class="btn-group" role="group">
  <input type="radio" class="btn-check" name="view" id="v1" checked>
  <label class="btn btn-outline-secondary" for="v1">List</label>
  <input type="radio" class="btn-check" name="view" id="v2">
  <label class="btn btn-outline-secondary" for="v2">Grid</label>
</div>

<div class="btn-toolbar">…groups…</div>
```

`btn-group-vertical`, `btn-group-sm` and `btn-group-lg` do what they say.

**Close button** — the cross is a mask, so it takes the colour of the text
around it:

```html
<button class="btn-close" aria-label="Close"></button>
<button class="btn-close btn-close-white" aria-label="Close"></button>
```

### Forms

Styled **by class**. A bare `<input>` only inherits the page's font, so
checkboxes, third-party widgets and hidden fields are left alone.

```html
<div class="form-group">
  <label class="form-label" for="email">Email</label>
  <input class="form-control" id="email" type="email" placeholder="you@example.com">
  <div class="form-text">We never share it.</div>
</div>

<select class="form-select"><option>Brazil</option></select>
<textarea class="form-control" rows="4"></textarea>
<input class="form-control" type="file">
<input class="form-control form-control-color" type="color" value="#2563eb">
<input class="form-range" type="range">

<input class="form-control form-control-sm"> <input class="form-control form-control-lg">
<input class="form-control-plaintext" readonly value="Shown as text">
```

**Checkboxes, radios and switches:**

```html
<div class="form-check">
  <input class="form-check-input" type="checkbox" id="terms">
  <label class="form-check-label" for="terms">I agree</label>
</div>

<div class="form-check">
  <input class="form-check-input" type="radio" name="plan" id="p1" checked>
  <label class="form-check-label" for="p1">Monthly</label>
</div>

<div class="form-check form-switch">
  <input class="form-check-input" type="checkbox" role="switch" id="alerts">
  <label class="form-check-label" for="alerts">Email alerts</label>
</div>
```

`form-check-inline` puts several on one line. The indeterminate state
(`input.indeterminate = true`) is drawn as a dash.

**Input groups:**

```html
<div class="input-group">
  <span class="input-group-text">$</span>
  <input class="form-control" aria-label="Amount">
  <button class="btn btn-outline-secondary">Apply</button>
</div>
```

**Floating labels** — the field needs a placeholder, a single space is enough:

```html
<div class="form-floating">
  <input class="form-control" id="name" placeholder=" ">
  <label for="name">Full name</label>
</div>
```

**Validation.** Three sources, one look:

```html
<!-- The server marks the field -->
<input class="form-control is-invalid" aria-describedby="name-error">
<div class="invalid-feedback" id="name-error">Use at least 3 characters.</div>

<!-- SFJS sets aria-invalid="true" and fills the feedback -->

<!-- Or the browser's own constraints, once the user has touched the field -->
<input class="form-control" required minlength="3">
```

`.is-valid` / `.valid-feedback` are the positive counterparts; `.was-validated`
on a form shows the browser's verdict on every field at once. Feedback with
nothing in it is not shown, so the element can always be rendered.

### Cards

```html
<div class="card">
  <img class="card-img-top" src="…" alt="…">
  <div class="card-header"><h3>Title</h3></div>

    <h5 class="card-title">Card title</h5>

</div>
```

Variables: `--card-padding-x`, `--card-padding-y`, `--card-radius`, `--card-bg`,
`--card-border-color`, `--card-cap-bg`.

### Badges

```html
<span class="badge">Default</span>
<span class="badge badge-primary">Primary</span>
<span class="badge badge-danger-subtle">Pale</span>
<span class="badge badge-success badge-pill">Pill</span>
```

### Alerts

```html
<div class="alert alert-warning" role="alert">
  <h4 class="alert-heading">Check your details</h4>
  Your card expires this month. <a class="alert-link" href="#">Update it</a>.
</div>

<div class="alert alert-success alert-dismissible" role="alert">
  Saved.
  <button class="btn-close" @dismiss aria-label="Close"></button>
</div>
```

Background, text and accent come from the colour's `-subtle`, `-emphasis` and
the colour itself, so every alert is readable in both themes.

### Tables

Styled by class, like forms:

```html
<div class="table-responsive">
  <table class="table table-striped table-hover">
    <caption>Users</caption>
    <thead><tr><th>Name</th><th>Role</th></tr></thead>
    <tbody>
      <tr><td>Ana</td><td>Admin</td></tr>
      <tr class="table-danger"><td>Bruno</td><td>Suspended</td></tr>
    </tbody>
  </table>
</div>
```

| Class | Effect |
|---|---|
| `table-striped` | Alternate rows shaded |
| `table-hover` | The row under the pointer shaded |
| `table-bordered` / `table-borderless` | Every cell bordered / no borders |
| `table-sm` | Compact cells |
| `table-align-middle` | Cells centred vertically |
| `table-{colour}` | On a table, row or cell |
| `table-responsive`, `table-responsive-{bp}` | Scroll sideways (below a breakpoint) instead of widening the page |

Stripes and hover paint a layer over the cell, so a `table-danger` row still
shows through them.

### Navs and tabs

```html
<ul class="nav nav-tabs">
  <li><a class="nav-link" aria-current="page" href="/">Overview</a></li>
  <li><a class="nav-link" href="/settings">Settings</a></li>
  <li><a class="nav-link" aria-disabled="true">Billing</a></li>
</ul>
```

`nav-tabs`, `nav-pills` and `nav-underline` are three looks; `nav-fill` and
`nav-justified` spread the items; `nav-vertical` stacks them. The current item is
the one marked `.active`, `aria-current="page"` or `aria-selected="true"`.
Interactive tabs — `role="tablist"`, arrow keys, panels — are SFJS's `@tabs`.

### Navbar

```html
<nav class="navbar navbar-expand-md">
  <a class="navbar-brand" href="/">SFPHP</a>
  <button class="navbar-toggler" @toggle="#menu" aria-label="Menu"></button>
  <div class="navbar-collapse" id="menu" hidden>
    <ul class="navbar-nav">
      <li><a class="nav-link" aria-current="page" href="/">Home</a></li>
      <li><a class="nav-link" href="/docs">Docs</a></li>
    </ul>
  </div>
</nav>
```

Stacked below the breakpoint, a row from it up; `navbar-expand` is a row at
every width. The collapse is shown above the breakpoint even while `hidden`.
`navbar-dark` is the light-on-dark version; `--navbar-bg` and the other
`--navbar-*` variables adjust it.

### Breadcrumb and pagination

```html
<nav aria-label="Breadcrumb">
  <ol class="breadcrumb" style="--breadcrumb-divider: '›'">
    <li class="breadcrumb-item"><a href="/">Home</a></li>
    <li class="breadcrumb-item" aria-current="page">Settings</li>
  </ol>
</nav>

<nav aria-label="Pages">
  <ul class="pagination">
    <li class="page-item disabled"><a class="page-link">Previous</a></li>
    <li class="page-item"><a class="page-link" href="?page=1">1</a></li>
    <li class="page-item"><a class="page-link" aria-current="page" href="?page=2">2</a></li>
    <li class="page-item"><a class="page-link" href="?page=3">Next</a></li>
  </ul>
</nav>
```

`pagination-sm` and `pagination-lg` change the size.

### Progress and spinners

```html
<div class="progress" role="progressbar" aria-valuenow="40" aria-valuemin="0" aria-valuemax="100">
  <div class="progress-bar" style="--value: 40%">40%</div>
</div>
<div class="progress"><div class="progress-bar progress-bar-success progress-bar-striped progress-bar-animated" style="width: 70%"></div></div>

<span class="spinner-border" role="status"><span class="visually-hidden">Loading…</span></span>
<span class="spinner-grow spinner-primary spinner-grow-sm" role="status"></span>
```

`--progress-height` and `--spinner-size` adjust them.

### Accordion

Built on `<details>` — it opens and closes without JavaScript, every screen
reader announces it as expandable, and find-in-page opens it. Items with the same
`name` close each other:

```html
<div class="accordion">
  <details class="accordion-item" name="faq" open>
    <summary class="accordion-header">Is there a free plan?</summary>
    <div class="accordion-body">Yes, for up to three users.</div>
  </details>
  <details class="accordion-item" name="faq">
    <summary class="accordion-header">Can I cancel?</summary>
    <div class="accordion-body">At any time.</div>
  </details>
</div>
```

### Dropdowns, popovers and tooltips

All three are native popovers: the browser puts them in the top layer (never
clipped by a card, no `z-index` to manage), closes them on Escape or a click
outside, and returns focus. SFJS ties each one to its button; where CSS anchor
positioning exists, CSS then places it, and elsewhere SFJS computes the
position. No positioning library is involved.

```html
<button class="btn btn-secondary dropdown-toggle" popovertarget="account">Account</button>
<div class="dropdown-menu" id="account" popover role="menu">
  <span class="dropdown-header">Signed in as Ana</span>
  <a class="dropdown-item" role="menuitem" href="/profile">Profile</a>
  <hr class="dropdown-divider">
  <button class="dropdown-item" role="menuitem">Sign out</button>
</div>

<button class="btn btn-outline-primary" popovertarget="help">Help</button>
<div class="popover" id="help" popover>
  <div class="popover-header">About this field</div>
  <div class="popover-body">Used only for delivery.</div>
</div>

<button class="btn" @tooltip="Copy to clipboard" aria-label="Copy">📋</button>
```

`dropdown-menu-end` aligns a menu to the end of its button.
`@tooltip-placement="bottom|left|right"` places a tooltip (top is the default):
SFJS sets the matching `tooltip-{side}` class on the tooltip, which SFCSS uses
to position it. Keyboard navigation of menus and the tooltip itself come from
SFJS (`sfjs.min.js`).

### Modals and offcanvas

Both are `<dialog>`. Opened with `showModal()` (SFJS: `@modal="#id"`), the
browser makes the rest of the page inert, keeps the focus inside, closes on
Escape and returns the focus to what opened it. The page behind does not scroll.

```html
<dialog class="modal" id="confirm" aria-labelledby="confirm-title">
  <div class="modal-header">
    <h2 class="modal-title" id="confirm-title">Delete project?</h2>
    <button class="btn-close" @dismiss aria-label="Close"></button>
  </div>
  <div class="modal-body">This cannot be undone.</div>
  <div class="modal-footer">
    <button class="btn" @dismiss>Cancel</button>
    <button class="btn btn-danger">Delete</button>
  </div>
</dialog>

<dialog class="offcanvas offcanvas-end" id="filters" aria-label="Filters">
  <div class="offcanvas-header">
    <h2 class="offcanvas-title">Filters</h2>
    <button class="btn-close" @dismiss aria-label="Close"></button>
  </div>
  <div class="offcanvas-body">…</div>
</dialog>
```

Sizes: `modal-sm`, `modal-lg`, `modal-xl`, `modal-fullscreen`, or
`--modal-width`. Offcanvas sides: `offcanvas-start`, `-end`, `-top`, `-bottom`,
sized by `--offcanvas-size`.

### Toasts

`sf.toast('Saved.', { variant: 'success' })` creates them — see SFJS. The stack
is a live region, so each toast is announced. Static markup:

```html
<div class="toast-stack">
  <div class="toast toast-success" role="status">
    <div class="toast-body">Saved.</div>
    <button class="btn-close" @dismiss aria-label="Close"></button>
  </div>
</div>
```

### Layout helpers

| Class | What it does |
|---|---|
| `container`, `container-fluid`, `container-{bp}` | A centred column whose widths are the breakpoints; `-fluid` is always full width; `-md` is fluid below `md` |
| `grid` + `grid-cols-{1–12}` | CSS grid; `md:grid-cols-3` changes it per breakpoint |
| `grid-auto-fit`, `grid-auto-fill` | With `grid`: as many columns as fit, no breakpoint needed; `--grid-min` sets the narrowest |
| `col-span-{n}`, `col-span-full`, `col-start-{n}` | Where an item sits in the grid |
| `hstack`, `vstack` | A row or a column with a gap (`--stack-gap`) |
| `ratio ratio-16x9` | A box of a fixed shape, for iframes and videos (`1x1`, `4x3`, `21x9`, or `--ratio`) |
| `stretched-link` | Makes the whole nearest positioned ancestor clickable |
| `sticky-top`, `fixed-top`, `fixed-bottom` | Pinned bars |
| `vr` | A vertical rule inside a flex row |
| `text-truncate`, `line-clamp` | One line with an ellipsis; several (`--lines`) |
| `img-fluid`, `img-thumbnail`, `figure` | Images that fit, framed, captioned |
| `clearfix` | Contain floats |

### Typography

Headings, paragraphs and lists are styled as themselves. Also: `lead`,

`mark`, `blockquote` with `blockquote-footer`, `list-unstyled`, `list-inline`
with `list-inline-item`, and `code`, `kbd`, `pre`.

## Utilities

Margin and padding (`m-3`, `px-4`, `mt-auto`, `ms-2`), gap, width and height,
display, flexbox, grid, typography, colour, borders, radius, shadows, opacity,
position, overflow, z-index, object-fit, aspect ratio, cursor and more — with
`hover:`, breakpoint and `print:` variants where they make sense. The complete
list, with values: [utilities reference](SFCSS_UTILITIES.md).

**Write the base class first, then the breakpoints.** The prefixes are
`min-width`, so the unprefixed class is what small screens get:

```html
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4">…</div>
```

## CSS variables

Everything the components read is a variable on `:root`, and can be set there,
on a section, or on one element:

```css
:root {
  --radius: 0.25rem;          /* .rounded, buttons, fields, dropdowns… */
  --surface: #fafafa;         /* the page */
}

.checkout {
  --primary: #047857;
  --primary-rgb: 4 120 87;
}
```

Setting `--primary` by hand does not recompute `--primary-contrast` and the
other derived values — the builder does that. To change a colour for the whole
site, change it in the config and rebuild.

| Group | Variables |
|---|---|
| Surfaces | `--surface`, `--surface-raised`, `--surface-sunken`, `--surface-border`, `--surface-border-strong`, `--body-color`, `--body-color-muted`, `--code-color` |
| Each colour | `--{c}`, `--{c}-rgb`, `--{c}-contrast`, `--{c}-hover`, `--{c}-active`, `--{c}-subtle`, `--{c}-border`, `--{c}-emphasis`, `--{c}-text` |
| Focus | `--focus-ring`, `--focus-ring-color` |
| Scales | `--spacing-{n}` (`--spacing-0_5` for the 0.5 step), `--font-size-{name}`, `--font-weight-{name}`, `--radius`, `--radius-{name}`, `--shadow`, `--shadow-sm`, `--shadow-lg`, `--transition` |
| Layout hooks | `--container-padding`, `--grid-min`, `--stack-gap`, `--lines`, `--ratio`, `--value` (progress bar), `--breadcrumb-divider`, `--gradient-from`, `--gradient-to` |
| Type | `--font-family`, `--font-family-mono`, `--line-height` |
| Borders | `--border`, `--border-width`, `--border-color`, `--border-radius` |
| Components | `--btn-*`, `--card-*`, `--badge-*`, `--alert-*`, `--table-*`, `--nav-link-*`, `--navbar-*`, `--page-*`, `--list-group-*`, `--progress-*`, `--spinner-size`, `--accordion-*`, `--modal-*`, `--offcanvas-size`, `--toast-accent`, `--tooltip-*` |

## Upgrading from 0.27

What changes for a page written against the previous stylesheet:

| Before | Now |
|---|---|
| Every `<input>`, `<select>`, `<textarea>` styled | Add `form-control` / `form-select` (and `form-check-input` for checkboxes) |
| Every `<table>` styled, every row highlighted on hover | Add `table` (and `table-hover` if you want the highlight) |
| `* { margin: 0; padding: 0 }` | Lists keep their indentation; headings, paragraphs and lists get a bottom margin |
| `w-3`…`w-8`, `h-3`…`h-8` were 1rem…3rem | They follow `n × 0.25rem`: `w-8` is 2rem, like `w-10`…`w-64` already did (`w-80` and `w-96` are new) |
| `md:p-3` was 0.75rem while `p-3` was 1rem | Both are 1rem; every breakpoint class reads the same scale as its plain class |
| `sm:` started at 480px, the container at 640px | Both at 640px |
| A max-width block forced `md:grid-cols-*` to one column below 768px and applied `md:p-2` everywhere | Removed — breakpoint classes are `min-width` only |
| `primary` `#3b82f6`, `success` `#22c55e`, `danger` `#ef4444`, `info` `#06b6d4` | `#2563eb`, `#15803d`, `#dc2626`, `#0e7490`: the shades that carry white text at 4.5:1 |
| `lime` and `emerald` were other families' colours, `orange` was one shade off | Corrected, with seven smaller slips in other families |
| `--xs` … `--xl` spacing variables, `--font-size-size-2xl` | `--spacing-{n}`, `--font-size-2xl` |

## Size and compatibility

| | |
|---|---|
| Classes in total | **3,836** |
| — base utilities and components | 2,091 |
| — `hover:` variants | 628 |
| — breakpoint variants (`sm` `md` `lg` `xl`) | 1,096 (274 per breakpoint) |
| — `print:` variants | 21 |
| Palette classes | 600 (20 families × 10 shades × `bg`/`text`/`border`) |
| CSS variables | 194 |
| Raw · minified | 237KB · 195KB |
| **Gzipped** | **33.1KB** |
| Dependencies | none |
| JavaScript | none — the interactive components use SFJS |

A project that wants less turns off what it does not use: `components: false`
saves about 8KB gzipped, `hoverVariants: false` about 4.7KB, an empty
`colorPalettes` about 9.5KB.

Works in every current browser. Anchor positioning (for dropdowns and tooltips)
and `:user-invalid` are used where the browser has them; elsewhere SFJS positions
popovers and validation falls back to the classes and ARIA attributes.
