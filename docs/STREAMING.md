# HTTP Streaming

Send and receive HTTP responses in chunks instead of buffering the entire body. Enables real-time data, large file transfers, and server-to-client proxying without memory overhead.

## Required PHP Extensions

Before using streaming, ensure these extensions are installed:

### Essential

```bash
# GD — Image generation for PWA icons
apt install php8.3-gd

# curl — HTTP client requests
apt install php8.3-curl
```

Verify installation:
```bash
php -m | grep -E 'gd|curl'
# Output should show both: curl, gd
```

### Optional (Recommended)

```bash
# mbstring — Better UTF-8 handling
apt install php8.3-mbstring
```

If `mbstring` is not installed, streaming still works but UTF-8 edge cases may be less robust. The framework runs without it (PHP 8.1+).

### Check Your Server

```bash
php -r "
echo 'Extensions:\n';
echo '  curl: ' . (extension_loaded('curl') ? '✓ installed' : '✗ MISSING') . '\n';
echo '  gd: ' . (extension_loaded('gd') ? '✓ installed' : '✗ MISSING') . '\n';
echo '  mbstring: ' . (extension_loaded('mbstring') ? '✓ installed' : '○ optional') . '\n';
"
```

## Server-to-Client Streaming

Send response body in chunks as data is generated. The client receives and processes each piece immediately, without waiting for the entire response.

### Use Cases

- **LLM output** — Send tokens as they're generated by an AI model
- **Large exports** — Stream CSV, NDJSON, or JSON arrays without buffering
- **Real-time updates** — Progress reports, log tails, live data
- **Server-Sent Events** — Browser subscribes to a stream of events
- **Proxy streams** — Receive from upstream service, forward to client

### Basic Usage

```php
use SfphpProject\src\Http\Response;
use SfphpProject\src\Http\StreamWriter;

return Response::stream(function(StreamWriter $out) {
    for ($i = 1; $i <= 100; $i++) {
        // Check if client disconnected
        if ($out->aborted()) {
            break;
        }

        $out->write("Item $i\n");
        
        // Simulate slow generation
        usleep(100000); // 100ms
    }
}, status: 200, headers: [
    'Content-Type' => 'text/plain; charset=utf-8',
]);
```

### How It Works

1. **Request arrives** → dispatcher creates Response::stream()
2. **Middleware runs** → can modify headers/status before emission
3. **Emitter sends headers** → client receives status 200, Content-Type, etc.
4. **Producer executes** → your callable starts running
5. **Each write() flushes** → data reaches client immediately
6. **Client processes** → can act on chunks as they arrive
7. **aborted() returns true** → if client disconnected

### StreamWriter API

```php
interface StreamWriter {
    /**
     * Write a chunk to the client.
     * Returns false if client disconnected (you should stop).
     */
    public function write(string $chunk): bool;

    /**
     * Check if client is still connected.
     */
    public function aborted(): bool;

    /**
     * Flush all output buffer levels.
     */
    public function flush(): void;
}
```

### Headers Sent Automatically

```http
Cache-Control: no-cache
X-Accel-Buffering: no
Content-Type: text/plain; charset=utf-8
```

These prevent proxy buffering and cache. If you need different caching:

```php
return Response::stream($producer)
    ->withHeader('Cache-Control', 'private, max-age=0')
    ->withHeader('X-Accel-Buffering', 'no');
```

### HEAD Requests

Sending a HEAD request to a streaming endpoint returns headers only:

```bash
curl -I http://example.com/stream
# HTTP/1.1 200 OK
# Cache-Control: no-cache
# Content-Type: text/plain
# (no body sent, producer does not run)
```

### Session Management

The session is automatically closed before streaming starts, preventing file locks:

```php
return Response::stream(function(StreamWriter $out) {
    // Session is already closed here
    // Writing to $_SESSION after this has no effect
    
    $out->write("Streaming data...");
});
```

If you need to save session data, do it before returning the Response:

```php
$_SESSION['started_stream'] = true;
session_write_close(); // Explicit (done automatically too)

return Response::stream(function(StreamWriter $out) {
    // Safe to stream now
    $out->write("Data...");
});
```

## Server-Sent Events (SSE)

Real-time events from server to browser. The browser opens a persistent connection and receives events as they're sent.

### ServerSentEvent Helper

```php
use SfphpProject\src\Http\Response;
use SfphpProject\src\Http\ServerSentEvent;

return Response::stream(
    function(StreamWriter $out) {
        $sse = new ServerSentEvent($out);

        // Send an event
        $sse->send('Processing...', event: 'status', id: '1');

        // With retry interval (milliseconds)
        $sse->send('Data chunk', event: 'data', id: '2', retry: 5000);

        // Heartbeat to keep connection alive
        $sse->heartbeat();

        // Multi-line data (each line is prefixed with 'data:')
        $sse->send("Line 1\nLine 2\nLine 3");
    },
    headers: ['Content-Type' => 'text/event-stream; charset=utf-8']
);
```

### Browser Consumption

```javascript
const es = new EventSource('/stream/sse');

es.addEventListener('status', (event) => {
    console.log('Status:', event.data);
});

es.addEventListener('data', (event) => {
    console.log('Data:', event.data);
});

es.addEventListener('error', () => {
    console.log('Connection lost');
    es.close();
});
```

### SSE Format

Each event is formatted as:

```
event: status
id: 1
data: Processing...

```

Multi-line data:

```
event: data
data: Line 1
data: Line 2
data: Line 3

```

Heartbeat (keeps connection alive, browser ignores):

```
: heartbeat

```

## Streaming in the Browser (SFJS `@stream`)

`sfjs-stream.js` reads a streamed response into a page element without any
JavaScript of your own. Load it after `sfjs.js`:

```html
<script src="{{ asset('js/sfjs.min.js') }}"></script>
<script src="{{ asset('js/sfjs-stream.min.js') }}"></script>
```

### Text streams

```html
<div id="output">Output appears here...</div>

<button @stream="/stream" @target="#output">Start streaming</button>
```

Each chunk is appended to the target as it arrives. The target receives the
chunks as **text**, not HTML, so the endpoint should answer with plain text
(`Content-Type: text/plain`). Markup sent down the stream would show up tag by
tag.

### Server-Sent Events

Add `@sse` to read the endpoint as an event stream. `@events` names the event
types to show, besides the default `message`:

```html
<button @stream="/stream/sse" @sse @events="status,progress,complete" @target="#events">
    Connect
</button>
```

A `GET` without a body uses `EventSource`. Any other method, or a request with
a body, reads the event stream through `fetch`.

### Attributes

| Attribute | Meaning |
|---|---|
| `@stream` | The URL to stream from |
| `@target` | The element that receives the output (default: the element itself) |
| `@sse` | Read the response as Server-Sent Events |
| `@events` | Comma-separated SSE event types to show |
| `@method` | HTTP method (default `GET`) |
| `@body` | JSON request body |
| `@trigger` | The event that starts the stream |
| `@abort` | Selector of an element whose click stops the stream |

### When a stream starts

Without `@trigger`, the rule is the same as the rest of SFJS: **a click starts
a button or link, a submit starts a form**. Any other element starts streaming
on its own when the page loads. A button inside a form streams on click and
sends the form's fields as the body when the method is `POST`, `PUT` or
`PATCH`.

Starting again replaces the run in progress. A second click stops the stream
that is still arriving, clears the target and streams from the beginning, so
the output of two runs never mixes in one box. `@abort` stops the current run
and leaves what already arrived in place.

State-changing methods send the page's `<meta name="csrf-token">` as
`X-CSRF-Token`.

## Client-Side Streaming (HTTP → PHP)

Receive large responses from upstream services in chunks, without buffering the entire body.

### Use Cases

- **Large file download** — Stream to disk without loading in memory
- **Real-time data** — Process as it arrives from an API
- **Proxy stream** — Receive from upstream, forward to client (combine with server streaming)
- **Monitoring** — Listen to a log stream or event feed

### Basic Usage

```php
use SfphpProject\src\Http\Http;
use SfphpProject\src\Http\ClientStreamListener;

Http::stream('/api/export.csv', new class implements ClientStreamListener {
    public function onChunk(string $chunk): bool {
        // Process each chunk as it arrives
        echo $chunk; // or file_put_contents, accumulate, etc.
        
        // Return false to abort the transfer
        return true;
    }

    public function onComplete(int $statusCode, array $headers): void {
        // Called after transfer complete or failed
        if ($statusCode !== 200) {
            error_log("Export failed: HTTP $statusCode");
        }
    }
});
```

### ClientStreamListener API

```php
interface ClientStreamListener {
    /**
     * Called repeatedly as chunks arrive.
     * @param string $chunk The data received
     * @return bool True to continue, false to abort
     */
    public function onChunk(string $chunk): bool;

    /**
     * Called after the last chunk or if an error occurs.
     * @param int $statusCode The HTTP status code
     * @param array<string, string> $headers Response headers
     */
    public function onComplete(int $statusCode, array $headers): void;
}
```

### Status Before First Chunk

Headers and status are available before streaming starts:

```php
Http::stream('/api/export', new class implements ClientStreamListener {
    public function onChunk(string $chunk): bool {
        // This is called after status/headers are known
        return true;
    }

    public function onComplete(int $statusCode, array $headers): void {
        // Decision made BEFORE streaming?
        if ($statusCode === 401) {
            // Too late; you already received chunks
            // Check status in onChunk() and return false to stop
        }
    }
});
```

Better: return false from onChunk() to abort:

```php
Http::stream('/api/data', new class implements ClientStreamListener {
    private int $totalBytes = 0;
    private const MAX_SIZE = 1024 * 1024 * 100; // 100MB

    public function onChunk(string $chunk): bool {
        $this->totalBytes += strlen($chunk);
        
        if ($this->totalBytes > self::MAX_SIZE) {
            error_log('Stream exceeded size limit');
            return false; // Stop receiving
        }

        return true;
    }

    public function onComplete(int $statusCode, array $headers): void {
        echo "Done: $this->totalBytes bytes\n";
    }
});
```

### UTF-8 Safety

Multi-byte UTF-8 sequences may split across chunks. The client handler ensures they're never torn apart:

```php
// Input: bytes [E2, 98, 83] = ☃ (snowman, 3 bytes)
// If chunk ends after byte 1: [E2, 98]
// Next chunk: [83, ...]

// ClientStream holds the incomplete [E2, 98]
// onChunk() is NOT called with [E2, 98]
// Next chunk arrives [83, ...], combined to [E2, 98, 83]
// onChunk() called with complete ☃
```

This prevents processing libraries from choking on partial UTF-8.

### Chaining: Proxy Streams

Receive from upstream, send to client in one go:

```php
// GET /download/report
return Response::stream(function(StreamWriter $out) {
    Http::stream('/api/generate-report', new class($out) implements ClientStreamListener {
        public function __construct(private StreamWriter $out) {}

        public function onChunk(string $chunk): bool {
            // Forward each chunk to the client immediately
            return $this->out->write($chunk);
        }

        public function onComplete(int $statusCode, array $headers): void {
            if ($statusCode !== 200) {
                error_log("Upstream failed: $statusCode");
            }
        }
    });
});
```

## Server Configuration

Streaming requires proper server configuration to work reliably.

### PHP Built-In Server (`php -S`)

Works out of the box:

```bash
./sfphp serve
curl -N http://localhost:8000/stream
```

The `-N` flag disables curl's buffering, so you see chunks arrive over time.

### PHP-FPM + Nginx

Disable FastCGI buffering to allow real-time data:

```nginx
location ~ \.php$ {
    fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    
    # Critical: disable buffering
    fastcgi_buffering off;
    fastcgi_request_buffering off;
    
    # Or use the header from PHP
    # fastcgi_buffering on;
    # fastcgi_ignore_headers X-Accel-Buffering;
}
```

Or let the app send the header:

```nginx
fastcgi_buffering on;
# PHP sends X-Accel-Buffering: no, which takes precedence
```

### Apache + mod_php

Ensure output buffering is disabled:

```apache
<FilesMatch "\.php$">
    SetHandler "proxy:unix:/run/php/php8.3-fpm.sock|fcgi://localhost/"
    
    # Disable proxy buffering
    SetEnv proxy-nokeepalive 1
    SetEnv proxy-initial-not-pooled 1
    SetEnv proxy-sendcl 1
</FilesMatch>
```

Or with mod_deflate (compression):

```apache
<IfModule mod_deflate.c>
    # Don't compress streaming responses
    SetEnvIfNoCase Request_URI "^/stream" no-gzip
</IfModule>
```

### Caddy

Disable buffering for streaming responses:

```caddyfile
example.com {
    reverse_proxy localhost:9000 {
        # Disable buffering
        flush_interval -1
    }
}
```

### Load Balancers & Proxies

If traffic goes through a load balancer (HAProxy, Cloudflare, etc.), ensure it doesn't buffer:

- **HAProxy:** `option http-server-close` + don't set `timeout tunnel`
- **Cloudflare:** Disable "Rocket Loader" and "Auto Minify" for streaming endpoints
- **AWS ALB:** Streaming should work transparently

## Troubleshooting

### Data arrives all at once, not gradually

**Problem:** Chunks are buffered and sent together.

**Solution:**
1. Check `-N` flag in curl: `curl -N http://localhost:8000/stream`
2. Check PHP buffering:
   ```php
   while (ob_get_level() > 0) ob_end_clean();
   ```
3. Check server config (nginx: `fastcgi_buffering off`)

### Stream never starts

**Problem:** No data appears, connection hangs.

**Solution:**
1. Check extensions: `php -m | grep curl`
2. Verify headers sent: look for "200 OK"
3. Check if session is locking: streaming auto-closes session, but check logs

### Partial UTF-8 characters appear

**Problem:** Text looks corrupted with broken characters.

**Solution:**
1. Ensure mbstring is installed: `apt install php8.3-mbstring`
2. Set correct Content-Type: `'Content-Type' => 'text/plain; charset=utf-8'`
3. Streaming already handles boundaries; if corrupted, check the source data

### Browser shows incomplete response

**Problem:** SSE connection closes early or doesn't show all events.

**Solution:**
1. Check browser console for errors
2. Ensure EventSource() URL is correct
3. Verify server sends complete events (ends with `\n\n`)
4. Check that `onComplete()` isn't closing prematurely

## Performance Considerations

### Memory

Streaming uses minimal memory compared to buffered responses:

```
Buffered (1GB file): ~1GB RAM
Streamed (1GB file): ~1MB RAM (chunk size)
```

### Timeouts

Set reasonable timeouts:

```php
// Default: 15 seconds total
$http = Http::timeout(30);

// Connection timeout: how long to wait to connect
$http = Http::connectTimeout(5);

// For long streams, consider using a longer timeout or no timeout at all
// (Not yet implemented; currently uses php.ini max_execution_time)
```

### CPU

Streaming doesn't add CPU overhead vs. buffering. Both process the same data.

## Examples

### Example 1: Stream Log File

```php
return Response::stream(function(StreamWriter $out) {
    $file = fopen('/var/log/app.log', 'r');
    fseek($file, -10000, SEEK_END); // Last 10KB
    
    while (!feof($file) && !$out->aborted()) {
        $line = fgets($file);
        $out->write($line);
    }
    
    fclose($file);
}, headers: ['Content-Type' => 'text/plain']);
```

### Example 2: Stream Database Records

```php
return Response::stream(function(StreamWriter $out) {
    $query = 'SELECT id, name FROM users';
    $stmt = db()->query($query);
    
    $out->write("id,name\n");
    
    foreach ($stmt->fetchAll() as $row) {
        if ($out->aborted()) break;
        $out->write($row['id'] . ',' . $row['name'] . "\n");
    }
}, headers: ['Content-Type' => 'text/csv']);
```

### Example 3: Proxy Upstream Streaming

```php
return Response::stream(function(StreamWriter $out) {
    $client = Http::base('https://api.example.com');
    
    $client->stream('/large-file', new class($out) implements ClientStreamListener {
        public function __construct(private StreamWriter $out) {}
        
        public function onChunk(string $chunk): bool {
            return $this->out->write($chunk);
        }
        
        public function onComplete(int $statusCode, array $headers): void {
            if ($statusCode !== 200) {
                $this->out->write("\n[Upstream error: $statusCode]\n");
            }
        }
    });
}, headers: ['Content-Type' => 'application/octet-stream']);
```
